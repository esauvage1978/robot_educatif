## Pourquoi 10 ans est l'âge pivot

### 1. Transition Scratch → Python

À 10 ans, l'enfant :
- **Maîtrise Scratch** : boucles, conditions, variables OK
- **Lit Python** sans panique (« c'est comme Scratch mais écrit »)
- **Tape du texte** assez vite (10 mots/min mini)
- **Comprend indentation** et syntaxe simple

**C'est LE moment** d'offrir un robot **dual Scratch/Python** pour transition douce.

### 2. Projets longs et ambitieux

**30-90 minutes** par session = temps pour :
- Projet sur 3 jours (« station météo IoT »)
- Débogage complexe (« pourquoi le capteur retourne 0 ? »)
- Documentation et partage (« j'explique mon code »)

À 8 ans c'était trop, à 12 ans il veut déjà du C++ : **10 ans = Python parfait**.

### 3. Passage CM2-6e : besoins évoluent

**CM2** : sciences, technologie, projets longs  
→ Robot = **support SVT/techno** (environnement, mesures)

**6e** : début collège, autonomie, « je sais faire »  
→ Robot = **fierté sociale** (« je code en vrai Python »)

### 4. Connexion monde réel

À 10 ans, l'enfant veut :
- **IoT** : connecter robot au Wi-Fi, Alexa, smartphone
- **Données réelles** : température, distance, luminosité
- **Projets utiles** : alarme maison, arrosage plantes, minuteur

**Scratch seul = trop « jouet »**, Python + capteurs = **« vrai projet d'ingénieur »**.

## Critères de choix pour 10 ans

### 1. Dual Scratch/Python obligatoire

**Scratch** pour rassurer (« je connais déjà »)  
**Python** pour progresser (« je deviens grand »)

**Éviter** : robots Scratch-only (trop limités) ou Python-only (trop brutal)

**Idéal** : **transition fluide** avec mêmes blocs traduits en Python

### 2. Carte évolutive avec écran

**Écran intégré** (LEDs ou LCD) = :
- Affichage sans ordinateur (autonomie)
- Débogage visuel (« pourquoi ça s'arrête »)
- Projets nomades (horloge, thermomètre portatif)

**Éviter** : robots sans feedback visuel (frustrant)

### 3. IoT et connectivité

**Wi-Fi intégré** = projets web :
- Contrôle smartphone
- Récupérer météo en ligne
- Poster données sur serveur

**Bluetooth** = connexion tablette/PC sans câble

**À 10 ans**, connectivité = **porte ouverte vers IA, cloud, apps**.

### 4. Capteurs et extensions multiples

**Minimum** :
- Ultrason, ligne, lumière (comme 8 ans)
- **+** Gyroscope, accéléromètre (orientation 3D)
- **+** Micro, haut-parleur (son)
- **+** Ports GPIO (ajouter ses capteurs)

**Plus de capteurs** = **projets infinis sur 3-5 ans**.

### 5. Communauté Python francophone

**Tutos Python robot** en français = rare !

Privilégier :
- Marques avec docs FR (Makeblock, ELEGOO)
- Robots utilisés en collège (ressources profs)
- Compatibilité standards (Arduino, MicroPython)

## Erreurs à éviter

### 1. Sauter Python trop vite

**Erreur** : « Il connaît Scratch, je prends Arduino C direct »  
**Réalité** : Python = **marche intermédiaire indispensable**. C++ sans Python = mur de syntaxe.

**Solution** : **mBot2 dual Scratch/Python** = transition douce.

### 2. Sous-estimer importance IoT

**À 10 ans**, Wi-Fi/Bluetooth = **factor wow** :
- « Papa regarde, je contrôle le robot avec mon téléphone ! »
- « J'ai récupéré la météo de Paris en Python ! »

**Robot sans IoT** = vite limité à 10 ans.

### 3. Négliger la documentation Python

**Arduino** : 1 million tutos  
**Python robot éducatif** : 10× moins

**Vérifier avant achat** : existe-t-il tutos Python FR pour CE robot ?

**mBot2** : oui (Makeblock docs + communauté)  
**CyberPi** : oui (idem)  
**ELEGOO** : non (Arduino C principalement)

### 4. Oublier évolutivité

**À 10 ans** : Python simple  
**À 12 ans** : Python avancé + IA  
**À 14 ans** : Machine Learning, vision

**Robot évolutif** = économie 200€ sur 5 ans (vs racheter tous les 2 ans).

### 5. Pas assez de capteurs

**Scratch** : 3-4 capteurs suffisent  
**Python** : on veut **tout tester** (temp, humidité, gyro, micro, caméra)

**Robot avec peu de capteurs** = ennui rapide en Python.

## Activités clés pour 10 ans

### Mois 1 : Transition Scratch/Python (6-8 sessions)

**Semaine 1-2** : Refaire projets Scratch en **mode blocs Python** (mBlock)  
**Semaine 3** : Même projet ouvert en **texte Python** → comprendre équivalences  
**Semaine 4** : Premier projet **Python pur** (sans blocs)

**Objectif** : **Déclic** « ah c'est pareil, juste écrit différemment ! »

### Mois 2-3 : Projets IoT (8-10 sessions)

**Projet 1** : Station météo (afficher température sur écran robot)  
**Projet 2** : Contrôle smartphone (app mobile → robot)  
**Projet 3** : Récupérer météo en ligne (API OpenWeather)  
**Projet 4** : Poster données sur Google Sheets (logger capteurs)

**Objectif** : **Comprendre** « le robot peut parler au monde entier ».

### Mois 4-6 : Projets ambitieux (10-15 sessions)

**Livreur autonome** : suit ligne + évite obstacles + GPS (théorique)  
**Alarme connectée** : détecte mouvement + envoie notification smartphone  
**Jukebox vocal** : reconnaissance vocale + joue musique demandée  
**Dashboard web** : serveur HTTP embarqué, contrôle via navigateur

**Objectif** : **Projets longs** (3-5 jours) = fierté et portfolio.

**Ressources** : [Programmer avec Python](/programmation/python/) · [Projets intermédiaires](/programmation/python-intermediaire/)
